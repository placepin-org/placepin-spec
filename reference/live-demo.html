Implementation notes

Alphabet — 30 characters, 0123456789BCDFGHJKMNPQRSTVWXYZ. No vowels (so codes can't spell words) and no L (1/l/I confusion); 0 and 1 are safe to keep since O/I/L are already gone.
Genuinely hierarchical, written local-first — each block is a fresh 27,000-way split of the specific cell its coarser neighbour named, not an arbitrary slice of one flat global index. Block 3 (rightmost) alone names a real ≈137 km region; block 2 + 3 narrows to ≈840 m inside it; all three blocks narrow to a ≈5 m leaf cell. A short code drops characters from the left, not the right — the region you're in survives truncation, not the exact spot.
Exact utilisation — a cycling largest-remainder apportionment hands out leftover rounding budget until every block hits exactly 100% of its 27,000-slot address space, at every level. Longitude is normalised to [-180°, 180°) first, so ±180° always encode identically.
Room to grow — the format is exactly nine characters today, with no reserved prefix. A future revision could add an explicit, visibly distinct X- extension prepended before block 1, for sub-leaf precision; see the spec for how that would work.
Client-side only — no network calls except map tiles. No pre-built lookup table: every encode/decode partitions its parent box on the fly. Deterministic, no external lookup service.
